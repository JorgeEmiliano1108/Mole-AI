Resumen ejecutivo
-----------------
Este informe documenta los cambios realizados para implementar la funcionalidad
"Self-Updating RAG" (knowledge harvesting) dentro del servicio `ai_rag_service` del
proyecto Mole-AI, y recoge además las modificaciones previas relevantes (Parte 1:
CNN Vision Client & PDF Summary). El objetivo principal fue añadir un flujo que
cuando FAISS devuelve baja similitud o ninguna coincidencia, consulte APIs
botánicas externas, deduplicate el contenido, genere embeddings y persista el
conocimiento tanto en Supabase (tabla `botanical_knowledge`) como en FAISS,
inyectando el nuevo conocimiento en el prompt del LLM para la misma petición.

Detalles técnicos relevantes
---------------------------
1) Dedupe
   - Se computa `content_hash = sha256(content.encode('utf-8')).hexdigest()`.
   - Antes de persistir, se consulta `knowledge_repo.get_by_hash(hash)`.
   - Si ya existe, se evita regrabar y se marca como "already_stored".

2) Orden de persistencia (Regla CRÍTICA de seguridad pedida por el usuario)
   - Persistir primero a Supabase (durable). Si la operación falla => NO
     persistir en FAISS. Esto mantiene consistencia entre la fuente durable y
     el índice local.
   - Si Supabase tiene éxito, luego persistir en FAISS (rápido local).
   - Si FAISS falla tras Supabase OK → log de error y reconciliación manual/posterior.

3) Metadatos guardados en FAISS
   - `metadata` utilizado: `{"source": "harvested:<origin>", "species": <scientific>, "content_hash": <sha256>}`

4) Uso en petición
   - El contenido harvestado se inyecta en `rag_context` para la construcción del
     prompt y se usa por el LLM en la misma petición, incluso si la persistencia
     posterior a Supabase/FAISS falla (en este caso, no se persiste nada).
