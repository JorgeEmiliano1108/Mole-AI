1. CONTEXTO
-----------
El modelo Django SensorLog usaba un patrón EAV (Entity-Attribute-Value):
    device_id | sensor_type | value | unit | location_x/y/z | timestamp

La tabla real en PostgreSQL (Supabase) es Wide Table:
    plant_id (UUID FK→user_plants) | recorded_at | soil_humidity |
    air_temperature | uv_index | light_level | ph_level

Se requirió alinear TODO el pipeline: ORM → serializers → views →
domain entities → application services → AI aggregator → mock IoT client.

3. DETALLE DE CAMBIOS
==============================================================================

a) models.py – SensorLog (managed=False)
   ANTES:  device_id, sensor_type, value, unit, plant_id (CharField),
           location_x/y/z, timestamp, created_at, user FK,
           SENSOR_TYPES choices, unique_together, EAV indexes
   DESPUÉS: plant_id (UUIDField), recorded_at (DateTimeField),
            soil_humidity, air_temperature, uv_index, light_level,
            ph_level (FloatField nullable), db_table='sensor_logs',
            managed=False, ordering=['-recorded_at']

b) serializers.py
   ELIMINADOS: SensorLogSerializer, LocationSerializer,
               SingleSensorSerializer, _SENSOR_TYPE_ALIASES
   NUEVOS:     SensorReadingSerializer (plant_id UUID, recorded_at,
               5 float opcionales – mínimo 1 requerido),
               SensorBatchSerializer (max 500),
               SENSOR_COLUMNS list (reemplaza SensorLog.SENSOR_TYPES en
               SensorDataQuerySerializer)

c) views.py
   sensor_data_view:  Un solo SensorLog.objects.create() plano (sin loop EAV)
   sensor_batch_view: bulk_create con list comprehension plano
   sensor_log_view:   Migrado a SensorReadingSerializer (legacy JWT endpoint)

d) entities.py
   ELIMINADO: SensorType enum (TEMPERATURE, HUMIDITY, LIGHT, etc.)
   SensorReading: plant_id, soil_humidity, air_temperature, uv_index,
                  light_level, ph_level, recorded_at
   is_critical(): Evalúa temperature>35/<5, humidity<10/>90, pH<4/>9

e) services.py
   ELIMINADO: import SensorType
   NUEVO:     SENSOR_FIELDS = ['soil_humidity','air_temperature',...]
   analyze_trend(readings, field): extrae valores con getattr(r, field)
   PlantMonitoringService: itera SENSOR_FIELDS en vez de SensorType enum

f) ai_models/services.py
   ELIMINADO: SENSOR_FIELD_MAP (6 entries), per-type query loop,
              device_id parameter
   NUEVO:     SENSOR_COLUMNS list, single query
              SensorLog.objects.filter(recorded_at__gte=...).order_by('-recorded_at').first()
              Lee columnas directamente con getattr(latest, col)

g) mock_iot_client.py
   ANTES:  EAV payload → {device_id, sensors: [{type, value, unit}, ...]}
   DESPUÉS: Flat payload → {plant_id, recorded_at, soil_humidity: 65.0,
            air_temperature: 25.3, uv_index: 5.2, light_level: 450.0,
            ph_level: 6.5, image_base64: ...}

7. NOTAS
==============================================================================
- managed=False: Django NO controla la DDL de sensor_logs; la tabla existe
  en Supabase y se administra con migraciones SQL directas.
- La migración 0003 es informativa (solo Meta options change) ya que
  managed=False impide ALTER TABLE automáticos.
- El SQLite local para dev fue recreado manualmente con la estructura
  Wide Table para que los tests funcionen.
