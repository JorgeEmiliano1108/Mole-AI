HEALTH CHECK & BUG REPORT

Fecha: 14 de marzo de 2026
Autor: Auditoría técnica automática (resumen)

RESUMEN EJECUTIVO
-----------------
Se realizó una auditoría estática del backend Mole.AI (servicio RAG/Visión). Se identificaron riesgos críticos de concurrencia en la inferencia TFLite y una práctica anti-patrón en el registro dinámico de rutas dentro del `lifespan` de FastAPI que producen rechazos de conexión y caídas del servicio. La persistencia dual (Supabase → FAISS) está correctamente diseñada y maneja excepciones apropiadamente.

1) 🐛 BUGS / CUELLOS DE BOTELLA DETECTADOS (con solución propuesta)
----------------------------------------------------------------
- Segfault / Crash por concurrencia TFLite (Crítico):
  - Descripción: `CNNVisionClient` usa un único `Interpreter` compartido y ejecuta la función de inferencia síncrona `_infer_pipeline` dentro de `asyncio.to_thread`. El runtime TFLite suele NO ser thread-safe: invocar `interpreter.invoke()` concurrentemente puede producir Segfaults que matan el proceso Uvicorn, dando lugar a `ERR_CONNECTION_REFUSED` en el frontend.
  - Prueba rápida: múltiples requests de inferencia simultáneos reproducirán el fallo en entornos con modelo nativo.
  - Solución propuesta (implementar ya):
    1. Añadir un `threading.Lock()` (o `threading.RLock`) en `CNNVisionClient` y envolver la zona que llama a `invoke()` (OOD + main) con `with self._invoke_lock:` para serializar acceso al `Interpreter` compartido.
    2. Alternativa: crear un pool de interpreters (uno por worker) o usar un worker externo (cola/servicio) para desacoplar inferencia.
    3. Logging y métricas: añadir contador de concurrencia y latencias para monitorizar.

- Registro de rutas dentro del `lifespan` (Severo — causa condiciones de carrera):
  - Descripción: `app.include_router(...)` se ejecuta dentro del `lifespan` (arranque async). Si el proceso recibe peticiones antes de que el router esté completamente inyectado, pueden producirse rechazos o comportamiento errático en el arranque.
  - Solución propuesta:
    1. Mover la inclusión de routers al nivel de módulo (es decir, construir/registrar rutas antes de arrancar uvicorn) o registrar routers en la creación del `app` (fuera del bloque `lifespan`).
    2. Si dependencias pesadas deben inicializarse en `lifespan`, usar proxies/objetos `None` que luego se rellenan por referencia, pero dejar la estructura de rutas registrada en el módulo principal.

- CORS y `ERR_CONNECTION_REFUSED` (observado en frontend):
  - Diagnóstico: `ERR_CONNECTION_REFUSED` suele indicar que no hay servicio escuchando. En este repo `docker-compose.yml` mapea `8002:8002` correctamente y el Dockerfile expone `8002`. El síntoma es consecuencia de crashes (Segfault) o bloqueo por registro dinámico de rutas.
  - Solución exacta: aplicar las dos correcciones anteriores (Lock + mover include_router). Verificar variable `PORT` y `HOST` en contenedor y healthcheck local. Reiniciar contenedores y validar `curl http://localhost:8002/api/v1/health`.

2) 🔍 REVISIÓN: `mole_ai_chat_use_case.py` — Persistencia dual
---------------------------------------------------------------
- Observación: El flujo de _harvesting_ persiste primero en Supabase dentro de un `try/except`, y solo si Supabase tiene éxito intenta escribir en FAISS; si Supabase falla, FAISS queda SKIPPED. Las excepciones se registran y devuelven el contenido para que la LLM use el dato en la respuesta actual.
- Evaluación: Diseño correcto — evita desincronización. Recomendación: añadir métricas y reintentos para FAISS con backoff, y un proceso de reconciliación asíncrono para fallos posteriores en FAISS.

5) RECOMENDACIONES PRIORITARIAS (ordenadas)
-------------------------------------------
1. Inmediato (blocker): Implementar `threading.Lock()` en `CNNVisionClient` para serializar `interpreter.invoke()`.
   - Archivo objetivo: `ai_rag_service/infrastructure/external/cnn_vision_client.py`.
   - Razonamiento: evita crashes del proceso de FastAPI y elimina `ERR_CONNECTION_REFUSED` causados por reinicios.
2. Alta: Mover `app.include_router(...)` fuera del `lifespan` y mantener la inicialización pesada dentro de `lifespan` mediante referencias inmutables o dependencias que luego se inyectan. Esto garantiza que el servidor esté listo para aceptar conexiones cuando uvicorn comience a escuchar.
3. Media: Añadir `asyncio.create_task()` para persistir imágenes rechazadas OOD como tarea fire-and-forget (Hard Negative Mining). Guardar metadatos (hash, timestamp, origen) y devolver inmediatamente el resultado de inferencia.
4. Mejoras operacionales: añadir healthchecks más robustos y métricas (Prometheus) para inferencia y cola de FAISS, y pruebas de carga del endpoint de visión (10–50 concurrencias) para validar el comportamiento.

6) PREGUNTA: ¿Agregar `asyncio.create_task` ahora o dejarlo para pulido?
---------------------------------------------------------------------
- Respuesta: Agregar `asyncio.create_task(...)` ahora mismo es recomendable. Es una mejora de bajo riesgo que captura datos valiosos para entrenamiento (hard negatives) sin bloquear ni alterar el flujo principal. Implementar con límites (ratelimit) y almacenamiento rotativo para evitar consumo descontrolado de disco.

ANEXO B — MODELOS USADOS POR EL SISTEMA
================================================================================

LLM (Large Language Model):
  Modelo:     deepseek-ai/DeepSeek-R1-Distill-Qwen-7B
  API:        HuggingFace Inference API (HF_INFERENCE_API_URL)
  Rol:        Generación de respuestas agrícolas, enriquecimiento LLM post-CNN,
              alertas tácticas. Es el "cerebro" conversacional de Mole-AI.

Embedding Model (RAG):
  Modelo:     BAAI/bge-small-en-v1.5
  Rol:        Vectorización de documentos/chunks para FAISS. Permite búsqueda
              semántica en la base de conocimiento botánico.

Vision Model (alternativa cloud):
  Modelo:     deepseek-ai/deepseek-vl2-tiny
  Backend:    VISION_BACKEND=deepseek (DeepSeekVisionClient)
  Rol:        Análisis visual de imágenes de plantas vía API cloud.
              Fallback del cliente CNN local.

CNN Local (on-device TFLite):
  Modelo:     MobileNetV3 / EfficientNet (custom .tflite)
  Archivos:   /models/cnn.tflite + /models/labels.json
  Rol:        Clasificación local de enfermedades de plantas. Sin costo de API,
              baja latencia. Input estándar: 224×224 RGB.

OOD Gatekeeper (pre-filtro):
  Modelo:     Binario Plant-vs-NotPlant (.tflite)
  Archivo:    /models/ood.tflite
  Threshold:  0.60 (configurable via OOD_THRESHOLD)
  Rol:        Rechaza imágenes que no son plantas antes de gastar cómputo
              en el clasificador CNN principal.
