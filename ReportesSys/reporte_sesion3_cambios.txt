C. BUG FIXES CRÍTICOS — Análisis de Regresión
================================================================================

Se realizó un análisis estático profundo de la cadena completa:
  Django ingest → FastAPI /explain-ph → ExplainPhUseCase → SupabaseKnowledgeRepo

Se encontraron 3 defectos que podrían causar HTTP 500 en producción:

───────────────────────────────────────────────────────────────────────────
FIX-1 · Campo fantasma en PhExplainResponse (CRÍTICO — HTTP 500)
───────────────────────────────────────────────────────────────────────────
  Archivo:  ai_rag_service/infrastructure/api/contracts.py
  Línea:    ~156 (clase PhExplainResponse)

  Problema:
    El modelo Pydantic tenía un campo `models: Dict[str, Any] = Field(...)`
    marcado como required. Sin embargo, el endpoint `explain_ph` en routes.py
    NUNCA devuelve este campo. Pydantic lanzaría ValidationError en cada
    respuesta, causando HTTP 500 incluso cuando la lógica de negocio funciona.

  Corrección:
    Eliminado el campo `models` de PhExplainResponse.
    Los campos restantes coinciden exactamente con PhExplanationResult (dataclass).

  Impacto: BLOQUEANTE — el endpoint /explain-ph no podía devolver respuestas.

───────────────────────────────────────────────────────────────────────────
FIX-2 · sensors=None causa TypeError (ALTO)
───────────────────────────────────────────────────────────────────────────
  Archivo:  ai_rag_service/application/use_cases/explain_ph_use_case.py
  Línea:    ~71 (método execute)

  Problema:
    Si `sensors` llega como None (campo opcional en PhExplainRequest con
    default_factory=dict, pero posible vía invocación directa), la línea
      {**sensors, "alerts": sensor_alerts}
    lanza TypeError: cannot unpack None.

  Corrección:
    Añadido `sensors = sensors or {}` como primera línea del método execute().

  Impacto: TypeError en runtime si sensors=None.

───────────────────────────────────────────────────────────────────────────
FIX-3 · NULL parcial en columnas pH de Supabase (MEDIO)
───────────────────────────────────────────────────────────────────────────
  Archivo:  ai_rag_service/infrastructure/database/supabase_knowledge_repo.py

  Problema (get_ph_tolerance):
    Solo se validaba `ideal_ph_min is None`. Si `ideal_ph_max` o
    `ideal_ph_optimal` eran NULL, `float(None)` lanzaría TypeError.

  Corrección (get_ph_tolerance):
    - Se extraen las 3 columnas a variables locales (ph_min, ph_max, ph_opt)
    - Se valida que NINGUNA sea None antes de convertir a float
    - Se amplió el except para capturar (HTTPStatusError, TypeError, ValueError)

  Problema (save_ph_tolerance):
    `data["min"]` y `data["max"]` lanzarían KeyError si el dict externo
    no incluía esas claves.

  Corrección (save_ph_tolerance):
    - Reemplazado `data["min"]`/`data["max"]` por `data.get("min")`/`data.get("max")`
    - Añadida validación explícita: si min o max es None, lanza ValueError
      con mensaje descriptivo antes de intentar el POST a Supabase.

  Impacto: TypeError/KeyError silencioso que corrompería el flujo de fallback.
